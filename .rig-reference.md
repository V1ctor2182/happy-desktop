# Rig TUI → Web/Desktop Client Reference

Engineering reference for building a web/desktop UI with feature parity to the Rig
TUI, derived from `node_modules/@slopus/rig/dist/` sources (compiled app + protocol).

- **Part A** — TUI feature/rendering survey (`dist/app/`).
- **Part B** — Protocol type shapes a client needs (`dist/protocol`, `dist/agent`,
  `dist/providers`, etc.).
- **Part C** — HTTP/SSE client surface (`dist/client/ProtocolHttpClient`).

The TUI renders to ANSI text; a web client should map the same *semantics* (roles,
symbols, colors, collapse/expand, truncation budgets) to DOM/CSS.

---

## Part A — TUI Feature Survey

### A1. Transcript entry model

The app maintains an ordered list of `AppTranscriptEntry`. One entry ≈ one rendered
block. Shape (`app/AppTranscriptEntry.d.ts`):

```ts
type AppTranscriptRole = "system" | "user" | "assistant" | "thinking" | "tool" | "event" | "error";
interface AppTranscriptEntry {
  id: string;
  role: AppTranscriptRole;
  text: string;
  title?: string;          // notice/tool label
  detail?: string;         // tool result / secondary line
  childText?: boolean;     // render text as indented child rows under title
  permissionReview?: string; // "Needs approval: … Risk: …"
  turnElapsedMs?: number;  // present → append turn-completion separator after entry
  completedTurn?: CompletedTurn;     // collapsed turn summary
  // Rich presentations (mutually exclusive per entry):
  fileDiffs?: readonly FileDiff[];   omittedFileDiffs?: number;
  execCommand?: ExecCommandPresentation;
  mcpToolCall?: CodexMcpToolCall;
  backgroundTerminalCompletion?: string;
  backgroundTerminalInteraction?: BackgroundTerminalInteractionPresentation;
  noticeChildren?: readonly NoticeChild[];
}
```

Entries are produced by reacting to `SessionEvent`s (see Part B). The dispatch order
in `#renderEntry` (precedence matters):
1. `role === "user"` → user bubble
2. `role === "assistant"` → agent markdown
3. `role === "thinking"` → thinking markdown (hidden unless "show reasoning" on)
4. `backgroundTerminalCompletion` → one-line notice
5. `backgroundTerminalInteraction` → header + input child rows
6. `execCommand` → shell command block
7. `mcpToolCall` → MCP tool block
8. `fileDiffs` (and not error) → file diff block
9. `role === "tool"` → generic tool block
10. `role === "error"` → notice (if no `detail`) or generic tool block styled as failure
11. `role === "event"` → notice (with `noticeChildren` or plain)
12. fallback → "System" notice

Between entries a blank line is inserted. Non-thinking filtering: `thinking` entries
are dropped from the visible list unless reasoning display is enabled.

### A2. Role rendering (symbols, color, styling)

ANSI constants: `BOLD \e[1m`, `DIM \e[2m`, `RESET \e[0m`. Theme supplies
`brand/primary/secondary/success/warning/error/accent`.

- **User** (`#renderUserEntry`): prefix `› ` (bold), text wrapped, rendered on an
  "input surface" (distinct background). Blank line above and below. Image
  placeholders styled as chips.
- **Assistant** (`#renderAssistantEntry`): prefix `• ` (dim). Body = full markdown
  (`renderAgentMarkdown` → `pi-tui` Markdown with syntax-highlighted code). Empty
  non-streaming text renders nothing. Streaming uses append-only render (A5).
- **Thinking** (`#renderThinkingEntry`): same `• ` dim prefix + markdown, but gated
  behind reasoning toggle; streams like assistant.
- **Notice / event / system / error** (`#renderNoticeEntry`): prefix `• ` in the
  role color (`warning` for event, `error` for error, `secondary` for system) +
  **bold title** + text. If `childText`, title on line 1 and text as `└ ` child rows.
- **Error**: same as notice but red `•`; with `detail` it renders as a failed tool.

### A3. Tool-call rendering variants

**Tool display name** (`humanizeToolName`): maps internal names to friendly labels —
`Agent`→"Subagent", `TaskList`→"Task list", `TaskOutput`→"Background output",
`spawn_agent`→"Start subagent", `wait_agent`→"Wait for subagents", `workflow`→
"Workflow", MCP `mcp__server__tool`→`Server · Tool`, else de-camel/humanize.

**Tool verb** (`#toolVerb`, active vs done): bash/exec→Running/Ran,
grep/find/glob/ls→Exploring/Explored, read/view→Reading/Read,
write/edit/patch→Editing/Edited, else Using/Used. Special states override:
stopped→"Stopped", error→"Failed", awaiting approval→"Awaiting approval".

**Status dot color**: `success` (done ok), `warning` (awaiting approval / active),
`error` (stopped/failed).

#### Generic tool (`#renderToolEntry`)
- Header: `● Verb DisplayText` — dot colored by status, verb brand+bold, text primary.
- Child rows (dim, `└ ` marker): `permissionReview` line if pending approval; then
  `detail` (tool result summary via `formatToolResultForDisplay`, `(empty result)`
  if empty). Errors wrap the detail; success shows single-line.
- Pending placeholder entries (title === text === PENDING) render as `• …` or nothing
  while the activity line is shown.

#### File diff (`renderCodexFileDiff`)
- Header: `• Verb path (+N -M)` where Verb = Added/Deleted/Edited by `diff.kind`
  (add/delete/update); `+N` green, `-M` red (exact counts from `diff.added/deleted`
  or computed).
- Body: per-hunk lines with left-gutter line numbers; `add`/`delete`/`context` line
  kinds get bg tint + syntax highlighting (`detectCodexDiffLanguage`, editor theme;
  dark/light palettes). Hunk breaks render `⋮`.
- Truncation: row budget (`maxRows`); overflow → `… N more lines`. Multiple files
  per tool capped (`MAX_DIFF_FILES_PER_TOOL`), overflow → `… N more files`; global
  row cap → `… N more rows`. `permissionReview` prepended as child row.

#### MCP tool (`renderCodexMcpToolCall`, `CodexMcpToolCall`)
```ts
interface CodexMcpToolInvocation { server: string; tool: string; arguments?: unknown; }
type CodexMcpToolCallStatus = "active" | "error" | "success";
interface CodexMcpToolCall { invocation; status; review?: string; result?: string | string[]; }
```
- Header dot colored by status (accent/success/error). Invocation shows
  `server tool {args}` — args JSON via `boundedJsonStringify` (≤4 KB), inline if it
  fits else wrapped with hanging indent.
- `review` rows (≤3) and `result` rows (≤5) rendered dim as child rows; result
  truncated. Interrupted → result "Interrupted.".

#### Exec / shell command (`renderExecCommand`, `ExecCommandPresentation`)
```ts
interface ExecCommandPresentation { type:"exec_command"; command:string; output:string; sessionId?:number; }
```
- Header: `● Verb <highlighted command>` — status dot (warning=running, success=ran,
  error=stopped/failed), verb "Running/Ran/Stopped/Failed". Command syntax-highlighted
  (`highlightShellCommand`), wrapped with hanging indent.
- When not active, output shown as dim child rows with head/tail truncation: keeps
  first/last ~5 lines, middle replaced by `… +N lines` / `… output truncated`;
  `(no output)` when empty.
- Child rows also include `review`/`detail` when present.

#### Background terminal / process
- `renderBackgroundTerminalCompletion`: dim `• Background terminal completed · <cmd>`.
- `renderBackgroundTerminalInteraction`: `↳ Interacted with background terminal · <cmd>`
  plus the input as child rows.
- Running summary line (footer area): `renderBackgroundTerminalSummary` →
  `N background terminals running · /ps to view · /stop to close`.

### A4. Completed turns

```ts
interface CompletedTurnStats { additions; deletions; elapsedMs; fileCount; toolCount; }
interface CompletedTurn { hiddenEntryIds: readonly string[]; stats: CompletedTurnStats; }
```
- When "compact completed turns" is on, `compactCompletedTurnEntries` collapses a
  finished turn's entries (hides `hiddenEntryIds`) into a single summary line:
  `renderCompletedTurnStats` → dim `• Worked for <elapsed> · N tools · N files · +A -D`.
- Otherwise each turn ends with `renderTurnCompletionSeparator(turnElapsedMs)`: a dim
  horizontal rule; if elapsed > 60s the rule embeds `─ Worked for <elapsed> ─`.

### A5. Streaming / append-only rendering

- `AppendOnlyStreamingRender<Entry>`: caches previously rendered lines per entry and
  only re-renders the tail as text grows during streaming — avoids reflowing the whole
  message each delta. `discard(entry)` on structural changes (e.g. markdown tables),
  `clear()` on reset.
- Assistant + thinking entries stream via their own append-only renderers. During a
  live run the streaming entry is identified by `#streamEntryId`; empty streaming body
  still reserves a blank line. Markdown tables bypass append-only (re-rendered, capped
  to `rows-8`).
- An **activity line** (spinner/wave, `renderActivityWave`) is shown as the last line
  while the agent is working (elapsed timer via `formatActivityElapsedTime`).
- **Pending steering messages** (`renderPendingSteeringMessages`): dim
  `• Messages to be submitted after next tool call (esc to send now)` + up to 3-line
  previews of each queued steer message.

### A6. Notices

A **notice** = titled non-transcript event/system/error message. `NoticeChild` =
`{ label, reason }` rendered as `label — reason` child rows under a bold title with a
colored `•` (`renderNoticeWithChildren`). Used for e.g. MCP server status changes,
tool availability, security notices.

### A7. Header / startup status card (`renderStartupStatusCard`)

Boxed card (`╭─╮…╰─╯`, dim border, max inner width 72) shown at top. Rows: `Rig
<version> · <session>`, then `Model: … · Reasoning: … · Provider: … [· Fast]`,
`Workspace: <path> · Environment: <env>`, `Access: <permission mode>`, and provider
usage rows (`formatStartupStatusUsageRows`). Narrow width falls back to packed lines.

### A8. Footer / status bar (`#renderForter`)

Composed dim, `·`-separated: model+reasoning (warning), cwd (success), active-agent
label, `queued N`, permission mode (lowercased), and usage summary when enabled.
Shell mode shows a red `Shell mode` line. Autocomplete replaces the footer when active.

### A10. Interactive menus / pickers

- **Model picker** (`/model`, `createSelectionPanel` + `describeModelChoice`/
  `encodeModelChoice`): lists provider→model options; selecting triggers `changeModel`
  ({modelId, providerId?, effort?}). Reasoning sub-choices from model `thinkingLevels`.
- **Reasoning/effort picker** (`/effort`, `describeReasoningLevel`): lists levels
  off/minimal/low/medium/high/xhigh/max/ultra with descriptions; marks current/default;
  triggers `changeEffort`.
- **Permission mode picker** (`/permissions`, `humanizePermissionMode`): Auto,
  Workspace write, Read only, Full access → `changePermissionMode`.
- **Service tier** (`/fast`): toggles `serviceTier: "fast"` via `changeServiceTier`.
- **Secrets menu** (`SecretMenuController`, `createSecretInputPanel`): list secret
  bundles (`SecretReference`: id/description/envVars); register/unregister; attach/
  detach to session or project scope → `attachSecret`/`detachSecret`.
- **Goal** (`/goal [pause|…]`): set objective (`setGoal`), change status
  active/blocked/complete/paused (`changeGoalStatus`), clear (`clearGoal`).

### A11. Monitors

- **Subagent monitor** (`/agents`, `createSubagentMonitor`, `renderSubagentSummary`):
  lists `SubagentSummary` sorted (`sortSubagentsForDisplay`) with description, status
  (`humanizeSubagentStatus`: Queued/Running/Completed/Stopped/Failed/Suspended/Idle),
  elapsed, tokens, latest text. Inline running summary: `N agents running · /agents to
  view · <elapsed> · <tokens> context tokens`.
- **Workflow monitor** (`/workflows`, `createWorkflowMonitor`, `renderWorkflowSummary`):
  lists `WorkflowRun` with status (`humanizeWorkflowStatus`: Running/Completed/Stopped/
  Failed), phase, agentCount, logs. Updates applied via `applyWorkflowRunUpdate` from
  `WorkflowRunUpdate` deltas. Inline: `N workflows running · /workflows to view`.

### A12. File-mention autocomplete

`@`-mention triggers `FileMentionAutocomplete`: `findFileMentionContext`/`findFileMentionPrefix`
detect prefix, `searchFiles` (server) returns `FileSearchResult{fileName,path}`,
`createFileMentionAutocompleteItems` builds items, `formatFileMention` inserts.

### A13. Keyboard / interaction affordances worth matching

- `esc` — flush pending steering messages now / interrupt; `/abort` stops the run.
- Slash `/` opens command palette; `@` opens file-mention autocomplete; arrow keys +
  enter to select in panels.
- Shell mode (prefix) runs a command directly (`runShellCommand`).
- Reasoning-visibility toggle (show/hide thinking entries).
- Compact-completed-turns toggle (collapse finished turns to one summary line).
- Truncation budgets are UX contracts: exec output head/tail (~5 lines each), diff
  rows per file/tool, MCP review (3) / result (5) rows — preserve "… N more" affordances.

### B8. `AgentLoopEvent` (inside `agent_event`)

Union = `AssistantMessageEvent` (streaming text/thinking/toolcall start/delta/end,

```ts
| { type:"context_compacted"; reason:"context_window"|"threshold"; compactedMessageCount; estimatedTokensBefore; estimatedTokensAfter:number }
| { type:"inference_iteration_start"; iteration:number }
| { type:"steering_applied"; messageIds:readonly string[] }
| { type:"inference_retry"; attempt; maxAttempts:number; reason:"connection_lost"|"incomplete_response" }
| { type:"tool_execution_start"; toolCall:ProviderToolCall }
| { type:"tool_execution_end"; result:Pick<ToolResultBlock,"toolCallId"|"toolName"|"type"|"display"|"failure"|"isError"|"presentation"> }
| { type:"tool_execution_progress"; toolCallId; display:string }
| { type:"tool_execution_status"; toolCallId; status:string }
| { type:"tool_batch_rejected"; toolCallIds:readonly string[] }
| { type:"permission_review"; toolCallId; action; reason:string; decision:"allow"|"ask"; risk:"low"|"medium"|"high"; userAuthorization:"low"|"medium"|"high" }
| { type:"background_processes_changed"; running:number; processes?:readonly BashSessionActivity[] }
| { type:"background_processes_stopped"; count:number }
```

These drive live UI: `tool_execution_start/progress/status/end` build+update tool
entries; `permission_review` populates `permissionReview` (Awaiting approval state);
`context_compacted` shows a compaction notice; `inference_retry` a retry notice.

via `getEvents(after=lastEventId)` after reconnect.

## Executive summary — key decisions for the chat surface

1. **Entry-per-block transcript** keyed by stable `id`; roles user/assistant/thinking/
   tool/event/error/system each have a fixed prefix + color contract (`›` bold user,
   `•` dim assistant/thinking, colored `•` for tools/notices).
2. **Render rich tool presentations**, not raw JSON: file diffs (`+N -M`, hunks,
   syntax highlight, "… N more"), exec commands (highlighted cmd + head/tail-truncated
   output), MCP calls (server·tool + bounded args + capped result rows), background
   terminals — chosen by `ToolResultPresentation`/entry fields, with generic tool
   fallback via `humanizeToolName` + `formatToolResultForDisplay`.
3. **Tool status is state, not text**: success/warning/error dot + verb
   (Running/Ran/Editing/Edited/Awaiting approval/Stopped/Failed) from tool name +
   live `tool_execution_*` / `permission_review` events.
4. **Streaming = append-only**: append tail deltas per entry (assistant + thinking),
   keep a live activity line with elapsed timer; finalize on `agent_message`.
5. **Turn boundaries**: separator with elapsed (>60s labeled), optional collapse of a
   completed turn into `Worked for … · N tools · N files · +A -D`.
6. **Reasoning is toggleable** and hidden by default; respect `internal` messages.
7. **Reconcile from `SessionEvent` union**; treat SSE as hints, re-hydrate durable
   state from `ProtocolSession`/`AgentSnapshot`, backfill by `EventId` on reconnect.
8. **Full control surface via slash palette + pickers**: model, effort/reasoning,
   permission mode, service tier ("fast"), secrets, goal, tasks, MCP, subagents,
   workflows, usage, plus session actions fork/reset/compact/rewind/abort/review.
9. **Affordances to match**: `/` command palette, `@` file-mention autocomplete,
   `esc` to flush steering/interrupt, pending-steering preview, permission-approval
   inline prompt, startup status card + footer status bar.
10. **User-input requests** (`user_input_requested`) render as multi-question option
    pickers answered via `answerUserInput` (`{answers: Record<id,string[]>}`).
